# Phase 4 held-out multi-package canary

This source slice provides one E2 task. `mavis eval e2 prepare-heldout` creates a fresh Git repository under `$MAVIS_HOME/evaluations/e2/tasks/` with two broken packages, a committed `BLUEPRINT.md`, a tracked dirty note, an untracked private draft, six failing baseline tests, and a retained baseline log. It is not a substitute for a large-project E2 shard.

After a current installed E0 all-pass summary exists, run the source observer with the **installed** Mavis package on `PYTHONPATH`, for example `PYTHONPATH=$HOME/.local/share/local-codex python3 local-codex/mavis/scripts/observe_heldout_e2.py` from the project root. The observer checks the E0 summary and installed executable fingerprint, temporarily hands the main model from IRIS to Mavis, launches the installed Mavis TUI, and asks for the catalog slice only. After its answer, enter `/compact`, wait for completion, then `/exit`. The observer runs the focused catalog tests from the host and checks that only the catalog package changed. It then starts a second installed process with `resume` and the same session ID. After its answer, enter `/exit`. The observer runs the complete six-test suite from the host, restores IRIS, and dispatches a separate read-only native Terra review through ZCode.

`mavis eval e2 verify-heldout MANIFEST.json` rechecks the result: exact installed candidate and model, current E0 receipt hashes, both host command/output receipts, protected file hashes, expected changed paths in both packages, first-session rollout prefix, real compaction event, task completions on both sides of the restart, distinct supervised process IDs, model restoration, and completed accepting native review. Missing or changed evidence fails closed. The observer writes a partial `result.json` on most failures and does not claim success from source tests.

This is one held-out task and one checkpoint across one compaction and restart. Broader Phase 4 coverage—large repositories, ambiguous failures, dependency repair, worktree conflicts, targeted test selection, tool discovery, and repeatable E2 shards—remains open. Installed execution and independent review must be performed after the final candidate is built and installed.
