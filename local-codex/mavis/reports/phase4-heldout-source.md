# Phase 4 held-out multi-package canary

This source slice provides one E2 task. `mavis eval e2 prepare-heldout` creates a fresh Git repository under `$MAVIS_HOME/evaluations/e2/tasks/` with two broken packages, a committed `BLUEPRINT.md`, a tracked dirty note, an untracked private draft, six failing baseline tests, and a retained baseline log. It is not a substitute for a large-project E2 shard.

After a current installed E0 all-pass summary exists, run the source observer with the **installed** Mavis package on `PYTHONPATH`, for example `PYTHONPATH=$HOME/.local/share/local-codex python3 local-codex/mavis/scripts/observe_heldout_e2.py` from the project root. The observer checks the E0 summary and installed executable fingerprint, takes the shared GPU lease, and loads only Mavis's model after proving IRIS idle and memory sufficient. IRIS keeps its model loaded. The observer drives both installed Mavis TUI processes through a private pseudo-terminal; it sends `/compact` and `/exit` only after the first native turn completes, and `/exit` after the resumed turn completes. The observer runs the focused catalog and full six-test commands from the host, unloads Mavis, releases the GPU lease, and dispatches a separate native Terra review through `codex exec --model gpt-5.6-terra --sandbox read-only`. It verifies that the review did not alter the fixture.

`mavis eval e2 verify-heldout MANIFEST.json` rechecks the result: exact installed candidate and model, current E0 receipt hashes, both host command/output receipts, protected file hashes, expected staged or unstaged changes in both packages, and distinct supervised process IDs. Each launcher prompt carries a random task marker. The observer finds exactly one rollout containing the first marker as a native user message, records that session and turn, and launches `resume` with that same session ID. The verifier requires the saved first and resume commands, both marked user turns and their matching task completions, with compaction between them in the same rollout. It also checks IRIS remained loaded, Mavis unloaded, the exact native Terra command, and a completed accepting Codex event stream whose final message matches the saved output. Missing or changed evidence fails closed. The observer writes a partial `result.json` on most failures and does not claim success from source tests.

This is one held-out task and one checkpoint across one compaction and restart. Broader Phase 4 coverage—large repositories, ambiguous failures, dependency repair, worktree conflicts, targeted test selection, tool discovery, and repeatable E2 shards—remains open. Installed execution and independent review must be performed after the final candidate is built and installed.
